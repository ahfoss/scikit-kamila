## Overview

scikit-kamila is a scikit-learn-compatible Python package (published as `kamila`) implementing KAMILA, a clustering algorithm for mixed continuous/categorical data. It is a port of the R package [ahfoss/kamila](https://github.com/ahfoss/kamila). The numerical core is C++ (bound with nanobind); the Python layer handles validation, initialization, and the scikit-learn API.

## Commands

The build uses scikit-build-core + CMake + nanobind, so the C++ extension `kamila._kamila_cpp` must be compiled before anything imports `kamila`. **After editing anything in `src/`, reinstall** (`pip install -e .`) or the tests will keep using the old compiled module.

```bash
pip install -e ".[dev]"          # build extension + all dev deps (test, lint, doc)

# Tests (CI requires 100% coverage; enforced via --cov-fail-under=100)
python -m pytest --cov=kamila --cov-report=term-missing --cov-fail-under=100
python -m pytest kamila/tests/test_kamila.py::test_parity_small_mixed   # single test

# Lint (CI runs both)
python -m ruff check .
python -m black --check .

# Docs (Sphinx + sphinx-gallery, output in doc/_build/html)
python -m sphinx -b html doc doc/_build/html
```

Pixi equivalents exist: `pixi run -e test test`, `pixi run -e lint lint`, `pixi run -e doc build-doc`.

Notes:
- pytest runs with `--doctest-modules`, so docstring examples in `kamila/` are executed as tests.
- `kamila/tests/test_doc.py` runs a full Sphinx build (including the gallery in `examples/`) as part of the test suite, so the `test` extra includes doc dependencies and a doc break fails tests.
- CI tests Python 3.9–3.15 on Linux, Windows, and macOS; keep code compatible with 3.9.
- `kamila/_version.py` is generated by setuptools-scm; don't edit it.

## Architecture

Three layers, called in order by `KamilaClustering.fit` / `predict` (`kamila/_kamila.py`):

1. **Validation / splitting** — `kamila/_validation.py::_validate_and_split_data` takes arbitrary `X` (ndarray or pandas DataFrame) plus the `categorical_features` spec (`None`, `'from_dtype'`, int indices, column names, or bool mask) and returns separate contiguous arrays: `X_con` (float64) and `X_cat` (int32, 0-indexed category codes), plus `categories`, `num_levels`, and per-block weights. Either block may be `None`. In `predict`, the fitted `categories_` / `is_categorical_` are passed back in so new data is encoded identically.
2. **Initialization / restarts (Python)** — `fit` either uses user-supplied `init_means` / `init_log_probs`, or runs `n_init` random restarts (uniform means within the continuous bounding box, symmetric Dirichlet category probabilities, drawn from `random_state`) and keeps the result with the lowest `objective`.
3. **C++ core** — `src/kamila_core.{hpp,cpp}` implements `kamila_loop` (the iterative algorithm, mirroring the R package's `kamilaLoopCpp`) and `kamila_predict`. `src/bindings.cpp` exposes them as `_kamila_cpp.kamila_loop_cpp` / `kamila_predict_cpp`, converting ndarrays to raw row-major pointers and returning a dict. Matrices cross the boundary as flat row-major buffers; categorical log-probabilities are a list of per-variable `(K, n_levels[q])` matrices. `has_con` / `has_cat` flags handle continuous-only and categorical-only data (null pointers for the absent block).

Fitted attributes are split by data type: `cluster_centers_con_` (K × n_con) and `cluster_centers_cat_` (list of log-prob matrices); continuous-only diagnostics are `None` when there are no continuous features, and vice versa.

## R parity testing

Correctness is primarily established by matching the reference R implementation. `scripts/generate_r_reference_data.R` (requires R with `kamila` and `jsonlite`) runs `kamila:::kamilaLoopCpp` with explicit initializations and writes JSON fixtures to `kamila/tests/data/`. The `test_parity_*` tests in `kamila/tests/test_kamila.py` load these fixtures, feed the same init into `KamilaClustering`, and compare results. When changing algorithm behavior in `src/`, parity tests are the main signal; regenerate fixtures only if the R reference itself changes.

`kamila/tests/test_common.py` (scikit-learn `parametrize_with_checks` via `kamila/utils/discovery.py`) is currently skipped.
